# Color — Semantic

역할 기반 토큰. 네이밍 패턴: `분류-용도`. 컴포넌트는 이 토큰만 참조한다.

**"참조 팔레트" 칸은 이 토큰이 실제로 무엇을 가리키는지다.** 컴포넌트에서 팔레트를
직접 쓰지 말라는 규칙이 있어 평소에는 몰라도 되지만, 새 토큰을 정할 때 옆 토큰이
어느 단계를 쓰는지 보면 고르기가 쉽다.

## 필요한 토큰이 없으면 여기에 새로 정의한다

**팔레트로 내려가지 않는다.** 쓰려는 역할에 맞는 토큰이 이 표에 없다는 것은
디자인 시스템에 아직 그 자리가 없다는 뜻이지, 팔레트를 직접 써도 된다는 뜻이 아니다.

```css
/* ❌ 토큰이 없어서 팔레트에서 꺼내 씀 */
border-color: var(--color-violet-600);

/* ✅ colors.css에 역할을 만들고 그것을 씀 */
--color-border-accent: var(--color-violet-600);   /* colors.css */
border-color: var(--color-border-accent);      /* 쓰는 쪽 */
```

**대비가 모자란다는 것도 팔레트를 쓸 이유가 되지 않는다.** 옆 역할의 토큰을
빌려오는 것도 마찬가지다 — `text-link`는 링크가 걸린 글자에만 쓴다.
쓰려는 색이 기준에 못 미치면 그것은 **이 파일이 고쳐질 자리**다.

새 토큰의 참조 단계는 옆 토큰을 보고 고른다. 쓰는 쪽 저장소가 아니라
**여기서 정의해야** 두 메이커가 같은 값을 본다.

2026-09-10에 `--color-border-accent`가 이 절차로 들어왔다. 선에 강조색이
필요했는데 `border`에 `default`와 `strong`밖에 없었다.

## Background

<BgColorTable />

`bg-overlay-blur`는 `bg-overlay`의 흰 블러 버전이다. 검정 딤은 그 위 버튼·글자가
잘 안 보인다는 지적이 있어서 만들었다 — 이미지처럼 밝기를 예측할 수 없는 콘텐츠를
전체 화면으로 덮을 때 쓴다. 아래처럼 `--blur-overlay`(backdrop-filter 값)와 항상
함께 쓴다:

```css
background: var(--color-bg-overlay-blur);
backdrop-filter: blur(var(--blur-overlay));
-webkit-backdrop-filter: blur(var(--blur-overlay));
```

**언제 쓰나** — 콘텐츠(이미지 등)에 시선을 집중시키고 싶을 때 쓴다. LayerPopup
(모달·바텀시트) 같은 기능적 overlay와는 맥락이 다르다 — 그쪽은 어떤 화면에서든
쓰는 범용 그릇이라 `--color-bg-overlay`(검정)를 그대로 쓰고 바꾸지 않는다.

**레이아웃 규칙**
- 우상단엔 항상 닫기 버튼을 둬서, 언제든 페이지를 벗어날 수 있게 한다.
- 좌상단엔 보조로 필요한 기능(삭제 등)을 둔다. 없으면 비워둔다.
- 위 두 자리는 IconButton을 쓴다 — 텍스트 버튼은 라벨 길이가 다 달라 두 자리가
  서로 안 맞고, 콘텐츠에 집중시키는 화면에서 글자가 이미지보다 눈에 먼저 들어온다.

### 세 단계를 고르는 법

**세 단계 모두 검정에 불투명도를 준 값이다**(2026-10-14). 회색 실선은 흰색이 아닌 면(연한 색 바탕, 사진)
위에서 제 색을 주장해 붕 떠 보였다. 불투명도는 밑에 깔린 색을 남기면서 경계만 잡는다.
그래서 그림 위에 얹는 선을 따로 두지 않는다(예전 `border-overlay`는 이때 걷고 `border-subtle`로 합쳤다).

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `border-default` | 검정 12% | **기본 구분.** 가장 많이 쓴다. 요소의 테두리, 섹션끼리의 구분 |
| `border-subtle` | 검정 8% | 같은 컨테이너 **안**의 미세한 구분(상자 안 콘텐츠끼리). 아바타·썸네일처럼 **그림이 들어가는 곳**의 가장자리 |
| `border-strong` | 검정 40% | 기본 구분선 사이에서도 **강한 구분**이 필요할 때. 가이드의 그림 테두리처럼 **선이 디자인으로 보일 때** |

`subtle`을 그림 가장자리에 쓰는 까닭은, 불투명도라서 그림 색과 어우러지면서도 바탕과는 갈리기 때문이다.
상자 안 콘텐츠끼리에 `default`를 쓰면 **선이 내용보다 먼저 눈에 들어온다.**

```css
/* ✅ 리스트 아이템 사이: 같은 컨테이너 안 */
.item + .item { border-top: 1px solid var(--color-border-subtle); }

/* ✅ 썸네일·아바타 가장자리: 그림이 들어가는 곳 */
.thumb { border: 1px solid var(--color-border-subtle); }

/* ✅ 버튼·상자의 테두리: 요소의 테두리 */
.btn { border: 1px solid var(--color-border-default); }

/* ✅ 필터와 리스트 사이: 섹션끼리의 구분 */
.filter-bar { border-bottom: 1px solid var(--color-border-default); }
```

**불투명도라서 생기는 일**

- **흰 바탕에서 값이 조금 달라졌다.** `strong`은 예전(gray-400 `#999`)과 같다. `subtle`은 예전(gray-100)보다 한 단 진하고(`#ebebeb`), `default`는 예전(gray-200)보다 조금 옅다(`#e0e0e0`).
- **선은 바로 밑에 깔린 색과 섞인다.** 테두리 밑에는 그 요소 자신의 배경이 깔린다. 그래서 틀에 바탕색을 칠하고 그 안에 그림을 넣으면, 선은 그림이 아니라 틀 바탕과 섞인다. 그림 색과 섞으려면 선을 그림 위(`::after`, `outline-offset: -1px`)에 얹는다(EditCanvas가 그렇게 한다).
- **어두운 면 위에서는 거의 안 보인다.** `bg-inverse`나 사진 위 진한 그늘 위의 선은 `border-oninverse`를 쓴다.
- **선 두 줄이 같은 자리에 겹치면 진해진다.** -1px 여백으로 이웃 테두리를 포개지 않는다.
- **면을 칠하는 데 써도 비친다.** 시트 손잡이·세로 구분 막대처럼 border 토큰으로 면을 칠하면 그 밑이 비친다.

`border-strong`과 `border-accent`는 쓰는 자리가 다르다. **`strong`은 같은 뉴트럴
계열에서 한 단계 진하게** 해서 구조를 가르는 선이고, **`accent`는 상태를 말하는
선**이다 — 고른 칩, 활성 탭, 편집기의 강조 안내선처럼 "지금 이것"을 가리킬 때 쓴다.

**고른 항목은 `border-primary`, 입력·조작 중인 곳은 `border-focus`다**(2026-10-01). `accent`는 뉴트럴 톤과
구분되는 강조가 필요할 때 쓰는 색인데, 고른 표시와 초점은 그만큼 강조될 자리가 아니다. 둘 다 `gray-900`을 참조한다.

- `border-primary`: 고른 미리보기 칸, 고른 견본·칩의 테두리.
- `border-focus`: 커서가 있는 입력칸 테두리(TextField, SearchField, ColorPicker의 hex 칸)와 키보드 포커스 링.

지금은 값이 같지만 역할이 달라 토큰을 갈랐다. 링만 더 드러나게 하거나 다크모드를 넣을 때 한쪽을 고치면
다른 쪽이 끌려가지 않는다(`bg-primary`와 `bg-inverse`를 가른 것과 같다).

**키보드 포커스 링은 `src/focus.css` 한 곳에서 두른다.** 따로 정하지 않은 모든 요소에 2px 링이다.
부품이나 앱이 outline을 적으면 그쪽이 이긴다. 링 색을 부품마다 다시 적지 않는다.

`border-accent`는 `bg-accent`(500)보다 한 단계 진한 **600을 참조한다.** 선은 글자보다 대비 기준이
낮은데(3:1), 하늘색 때는 500이 흰 배경에서 2.77이라 그마저 못 넘어 600으로 두었다(2026-09-10).
2026-09-29에 accent를 보라로 옮기면서 500도 3.61로 넘게 됐지만 `text-accent`와 같은 단계로 600(5.03)을 그대로 쓴다.
`bg-accent`(채움)와 나란히 놓으면 선이 반 단계 진하지만, 40px 상자에서는 같은 보라로 읽힌다.

`text-link`는 accent를 따라가지 않고 하늘색(`sky-700`)으로 남는다. 링크는 파랑이 관례다(2026-09-29).

## 배경·테두리 없는 단추의 상태색 (2026-10-26)

**배경·테두리 없는 neutral 단추는 상태를 글자(아이콘)색으로 보인다**(2026-10-26 사용자). 같은 모양인 Button `accent`도 따른다.
면이 없는 단추에 `bg-hover`·`bg-pressed`를 얹으면 없던 상자가 갑자기 생겨, 글자 하나가 상자로 바뀌어 보였다.

| 단추 | 기본 | hover | pressed |
|---|---|---|---|
| Button `neutral` | `text-default` (gray-800) | `text-hover` (gray-600) | `text-pressed` (gray-500) |
| Button `accent` | `text-accent` (violet-600) | `text-accent-hover` (violet-500) | `text-accent-pressed` (violet-400) |
| IconButton `neutral` | `icon-default` (gray-700) | `icon-hover` (gray-500) | `icon-pressed` (gray-400) |
| IconButton `neutral-weak` | `icon-tertiary` (gray-300) | `icon-secondary` (gray-500) | `icon-default` (gray-700) |

**옅어지는 쪽으로 정했다.** 진해지는 쪽은 gray-900 한 칸뿐이라 기본(800·700)과 거의 안 갈리고,
hover와 pressed도 서로 안 갈린다. `neutral-weak`만은 이미 gray-300이라 더 옅어질 자리가 없어 거꾸로 진해진다.
이것은 새 토큰을 두지 않고 아이콘의 기존 단계를 따라 올라간다.

`*-hover` 토큰은 앱(`maker-design-system/native`)에 담지 않는다. 앱에는 hover가 없다(`bg-hover`와 같다).
